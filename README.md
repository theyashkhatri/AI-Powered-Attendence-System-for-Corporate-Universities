# AI-Powered Attendance System for Corporate Universities

A computer-vision-based project for detecting, tracking, and counting people in video streams. This project is designed as a practical foundation for an AI-powered attendance system for corporate universities, classrooms, training rooms, and similar environments.

> **Project status:** The current implementation focuses on **person detection, object tracking, and counting**. The tracking IDs generated by the system are temporary object IDs and are **not employee/student identities**. A complete identity-based attendance solution would require an additional identity-recognition layer and attendance database.

---

## 1. Project Overview

Traditional attendance systems often require manual intervention. Computer Vision can be used to automate part of this process by analysing video frames and detecting people.

This project demonstrates the following pipeline:

```text
Input Video
     ↓
Frame Extraction
     ↓
Image Pre-processing
     ↓
MobileNet-SSD Object Detection
     ↓
Person Detection
     ↓
Bounding Boxes
     ↓
Non-Maximum Suppression
     ↓
Centroid-Based Object Tracking
     ↓
Unique Tracking IDs
     ↓
Person Counting / Visualization
```

The project uses Python, OpenCV, NumPy, SciPy, and imutils.

---

## 2. Objectives

The main objectives are to:

- Detect people from a video stream.
- Process video frame by frame.
- Generate bounding boxes around detected people.
- Filter detections to the `person` class.
- Track detected people across consecutive frames.
- Assign unique tracking IDs.
- Count tracked people.
- Display tracking information and FPS in real time.
- Provide a foundation that can be extended into a complete attendance application.

### File Description

#### `person_tracking.py`

The main application.

It:

1. Loads the MobileNet-SSD model.
2. Opens the input video.
3. Reads video frames.
4. Performs object detection.
5. Filters detections for people.
6. Creates bounding boxes.
7. Applies non-maximum suppression.
8. Sends bounding boxes to the centroid tracker.
9. Displays tracking IDs, FPS, and total person count.

#### `centroidtracker.py`

Contains the `CentroidTracker` implementation.

It maintains:

- Object IDs
- Object centroids
- Bounding boxes
- Disappeared-frame counters

The tracker matches current detections with previously tracked objects using centroid distances.

#### `MobileNetSSD_deploy.prototxt`

Contains the neural-network architecture used by the MobileNet-SSD detector.

#### `MobileNetSSD_deploy.caffemodel`

Contains the trained model parameters/weights.

#### `test_video.mp4`

Sample input video used for testing the application.

## 5. How the System Works

### Step 1 — Video Input

The application opens:

```python
cap = cv2.VideoCapture("test_video.mp4")
```

The video is processed frame by frame.

### Step 2 — Frame Processing

Frames are resized before inference:

```python
frame = imutils.resize(frame, width=600)
```

### Step 3 — Model Loading

The MobileNet-SSD model is loaded using OpenCV:

```python
detector = cv2.dnn.readNetFromCaffe(
    prototxt=protopath,
    caffeModel=modelpath
)
```

### Step 4 — Object Detection

Each frame is converted into a neural-network input blob and passed through the model.

```python
detector.setInput(blob)
person_detections = detector.forward()
```

### Step 5 — Person Filtering

The model supports multiple object classes. The application processes only detections classified as:

```text
person
```

A confidence threshold is also applied:

```python
if confidence > 0.5:
```

### Step 6 — Bounding Boxes

Detected people are represented using bounding boxes:

```text
(x1, y1) ---------------- (x2, y1)
   |                         |
   |         PERSON          |
   |                         |
(x1, y2) ---------------- (x2, y2)
```

### Step 7 — Non-Maximum Suppression

Multiple overlapping detections may refer to the same person. Non-Maximum Suppression is used to reduce redundant bounding boxes.

### Step 8 — Centroid Tracking

The centroid of each bounding box is calculated:

```text
cX = (x1 + x2) / 2
cY = (y1 + y2) / 2
```

The tracker compares current centroids with previously tracked centroids and attempts to maintain the same object ID.

### Step 9 — Tracking IDs

Example:

```text
ID: 0
ID: 1
ID: 2
```

These IDs identify tracked objects within the running tracking process.

> **Important:** `ID: 0` does not mean Employee 0 or Student 0. It is a tracking identifier generated by the application.

## 9. Tracker Configuration

The current tracker is initialized using:

```python
tracker = CentroidTracker(
    maxDisappeared=80,
    maxDistance=90
)
```

### `maxDisappeared`

Controls how many consecutive frames an object can be missing before it is deregistered.

### `maxDistance`

Controls the maximum centroid distance allowed when associating a current detection with an existing tracked object.

You can experiment with these parameters to observe their effect on tracking stability.

## 11. Detection vs Tracking vs Recognition

These concepts should not be confused.

### Detection

Answers:

> Where is the person?

### Tracking

Answers:

> Which detected object corresponds to the object tracked in previous frames?

### Recognition

Answers:

> Who is this person?

### Attendance

Answers:

> Should this person's presence be recorded, and under which identity?

The current repository demonstrates **detection + tracking + counting**.

It does not currently implement identity-based face recognition or an attendance database.

---

## 12. Limitations

The current implementation has several limitations:

- Tracking IDs are not permanent identities.
- The system does not identify students/employees by name.
- There is no face-recognition component.
- There is no attendance database.
- There is no user authentication system.
- Detection accuracy can be affected by lighting and camera position.
- Occlusion can affect detection and tracking.
- Crowded scenes may reduce tracking reliability.
- False positives and missed detections can occur.
- The current project is primarily a detection/tracking demonstration rather than a complete production attendance platform.
